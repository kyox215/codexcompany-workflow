# CodexCompany Workflow

一个面向 Codex 的产品与工程工作流 Skill。把 CodexCompany 日常使用的任务接续、经理协调、专业技能路由、实现和验收整理成一个可移植的包。适用于独立开发者、小团队和需要跨会话交付软件的人。

## 能做什么

| 场景 | 工作方式 |
| --- | --- |
| 新 App 或产品 | 从问题验证、首版范围和状态数据，到设计、纵向切片、实现、验收、发布准备和反馈。 |
| 已有功能或 Bug | 复用当前规则与技术栈，沿受影响的路径补规格、修复和回归。 |
| 文案或间距微改 | 改动目标位置并直接查看实际结果。 |
| 自主迭代或复杂需求 | 经理组织体验、工程和独立 QA，记录分歧、取舍与复测结果。 |
| 换会话继续任务 | 从当前项目的权威状态与交接继续，保留最新纠正、文件归属与证据范围。 |

## 安装

在要使用的项目根目录运行。若目标目录已有同名 Skill，请先检查其版本。

~~~sh
mkdir -p .agents/skills
git clone https://github.com/kyox215/codexcompany-workflow.git .agents/skills/codexcompany-workflow
~~~

如果下载的是 ZIP，将解压后包含 `SKILL.md` 和 `references/` 的文件夹命名为 `codexcompany-workflow`，放到项目的 `.agents/skills/`。想在本机各项目使用时，可选择放到 `~/.agents/skills/`。安装后在 Codex 的 Skill 列表中确认可见，必要时重启 Codex。 [OpenAI Docs](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills)

## 第一次使用

1. 在 Codex 中打开刚安装 Skill 的项目目录。
2. 从 Skill 选择器选中 `codexcompany-workflow`。支持 `$` 提及的客户端也可直接输入 `$codexcompany-workflow`。已经通过选择器选中时，可以直接发送后面的任务内容。
3. 说清想交付什么、要沿用哪些约定，以及怎样算通过。下面是一条可以复制的起始消息。

~~~text
$codexcompany-workflow 给现有记录列表加一个状态筛选。
沿用当前设计、数据接口和分页方式。先核对列表现状，再实现。
验收时检查状态切换、清空、空结果和失败重试。交付本地候选，
列出修改位置、验证命令、实际结果和待验证项。
~~~

如果列表有分页，预期是筛选整个数据集时，可以直接补一句「状态筛选应作用于整个结果集，切换筛选时回到第一页」。这种补充会改变查询和验收条件，值得明确写出来。

### 找不到 Skill 时

先检查从当前项目根能否看到 `.agents/skills/codexcompany-workflow/SKILL.md`，并确认 `references/` 与它同级。用 ZIP 安装时，留意是否多套了一层解压目录。确认 Codex 打开的是正确项目，必要时重启后再检查 Skill 列表。 [OpenAI Docs](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills)

## 在同一个对话里推进

| 你现在想做什么 | 可以直接发给 Codex |
| --- | --- |
| 先看方案 | 先检查现有行为，给我一份带验收条件的方案。先停在方案，我看完再决定是否实现。 |
| 继续实现 | 按刚才确认的规格实现筛选。本轮交付可在本地验证的候选。 |
| 补一条要求 | 更新刚才的筛选需求。切换筛选时回第一页，把这个场景补进验收。 |
| 缩小本轮范围 | 本轮只交状态筛选，保存筛选偏好放到下一轮。 |
| 看验收证据 | 用当前候选复测四个验收场景，逐项写出预期、实际结果和证据位置。环境不足的项标为未验。 |
| 准备交接 | 保存本轮决定、变更位置、候选版本、已验和待验项，以及下一个可执行动作。告诉我交接文件路径。 |

同一个对话里可以沿用已确认的规格和任务。纠正需求时，说清哪一条决定变了。如果打算切换会话，先让 Codex 留下一份可定位的交接。

## 按任务类型复制提示词

**从零做一个产品**

~~~text
$codexcompany-workflow 我想做一个给门店员工使用的维修登记工具。
首版让员工完成录入、保存和查回一张维修单。先明确用户路径、
必填项、失败提示和验收条件，再按最小可用切片实施。
交付可运行的本地候选，并说明怎么验证。
~~~

**修一个可复现的 Bug**

~~~text
$codexcompany-workflow 在记录列表切换状态后，页码停留在原来的第 3 页，
结果显示为空。先用现有数据或可控样本复现，定位原因并做局部修复。
复测切换状态、正常翻页和清空筛选，记录修复前后的结果。
~~~

**做一次复杂改造**

~~~text
$codexcompany-workflow 改造订单编辑流程，涉及权限、状态流转和保存失败恢复。
先确认当前业务规则，给出最小可交付切片和逐项验收条件。
环境支持且已授权时，安排产品或体验、工程和独立 QA 分工。
交付时区分作者自查与独立复测，标明待验证场景。
~~~

**改一处文案**

~~~text
把记录列表的空态文案改为「暂无符合条件的记录」。
在本地打开对应空态确认显示。
~~~

## 换一个对话怎么接着做

新对话从同一项目打开，重新选择或提及 Skill，并给真实任务号、请求键或交接路径。下面的 `C-123` 是示例，使用时换成你的任务号。

~~~text
$codexcompany-workflow 继续任务 C-123。先读本项目交接和最新决定，
核对任务归属、当前候选和已完成的验收，再处理下一项待办。
如果任务仍由另一个会话执行，先汇报交接状态。
~~~

采用目录模板时，按 `sourcePath` 找到项目根，在 `reportPath/deliveries/<真实任务号>/` 找到任务报告和验收证据。没有任务系统的个人项目，可以直接给现有交接文档的路径。 [目录与归档模板](references/project-layout.md)

如果希望项目默认采用这套方法，可在该项目的 `AGENTS.md` 加一句。

> 多步骤交付和任务接续按 codexcompany-workflow 选取步骤。复杂任务按授权安排独立验收，普通问答和微改走短流程。

## 包内入口

- [SKILL.md](SKILL.md) 根据任务大小决定下一步。
- [产品交付十阶段](references/delivery.md) 定义每一步的结果和通过条件。
- [协作与验收](references/operations.md) 明确经理、专业岗位、桌面排队与独立复测。
- [目录与归档模板](references/project-layout.md) 给出三分类、项目登记和按任务号归档示例。
- [接续与记忆](references/continuation.md) 处理项目归属、当前决定、任务接续与留档。
- [技能路由](references/routing.md) 按平台和步骤选择已有专业能力。
- [可复制模板](references/templates.md) 包含规格、页面、状态数据、切片、派工、验收、发布和交接。

本包是 CodexCompany 截至 2026-11-03 的工作方法公开版。使用现有项目目录和任务系统即可运行；没有专用台账时，可用项目文档保存简明接续记录。原公司任务库、内部运行工具、项目数据和第三方技能分别维护。专业技能和子代理是可选能力，依赖独立 QA 的结论仍需要独立证据。
