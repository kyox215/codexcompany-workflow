# 项目目录与交付归档

新项目先确定分类、唯一项目根、登记键和交付目录。已有项目先查登记和实际工作目录，功能、修复和原型沿原项目收纳。名称相似时核对是否同一项目。

```text
<公司根>/
├── company.json
├── 项目/
│   ├── 业务产品/
│   │   └── <project-slug>/     # 门店、客户或经营产品
│   ├── 工具与实验/
│   │   └── <project-slug>/     # 自动化、研究与独立原型
│   └── 个人事务/
│       └── <project-slug>/     # 个人财务、生活等独立项目
├── 项目入口/                   # 导航索引
├── scripts/                   # 公司管理脚本
├── state/                     # 公司运行状态
└── projects/                  # 按项目归档的管理记录
    └── <project-id>/
        └── deliveries/
            └── <真实任务号>/
                ├── REPORT.md
                └── QA.md      # 需要独立验收时
```

经理按用途选择三分类之一。项目根使用稳定的小写英文短横线命名，例如 `sample-tool`。项目 ID 是稳定的登记键，可以与目录名一致。同名先核归属，日期用在项目内部批次。

## 项目登记模板

把此对象合入团队的项目登记表。CodexCompany 使用 `company.json`。以下为示例，使用时替换路径和登记键。

```json
{
  "id": "sample-tool",
  "sourcePath": "/path/to/company/项目/工具与实验/sample-tool",
  "reportPath": "projects/sample-tool"
}
```

- `sourcePath` 是项目实际根的规范化绝对路径。执行前核对项目规则、Git 根或工作树、聊天 cwd 和文件所有权。根路径嵌套时，使用最具体的已登记项目根。原生项目 ID 未知就留空。
- `reportPath` 是相对公司根的项目报告目录。任务交付路径为 `<公司根>/<reportPath>/deliveries/<真实任务号>/`。例如任务系统实际返回 `C-123` 后，记录到 `projects/sample-tool/deliveries/C-123/`。使用团队任务系统的实际编号。

## 执行与归档模板

```text
项目 ID：
真实任务号：
项目工作目录（sourcePath）：
本轮产物路径：
临时输出路径：
证据目录（reportPath/deliveries/真实任务号）：
成果版本或哈希：
验证结果、未验范围和下一动作：
```

项目根内沿用已有结构。需要时可用 `docs/`、`design/`、`prototypes/`、`artifacts/`、`outputs/<任务或日期>/`、`history/`、`backups/` 或 `.tmp/<任务>/`。按本轮用途创建。派工、构建、预览和导出显式传入工作目录与输出位置，交付时核对实际落点。

源码和业务产物归项目根，管理报告、验收证据和交接归对应任务目录。报告链接实际产物，记录版本或哈希和验证范围。任务状态由既有任务系统维护。公司治理报告归 `projects/company/`，项目入口用于导航。

已有工程继续使用登记的旧根。迁移前核对 Codex 项目关联、聊天 cwd、Git 工作树和运行路径，确认可切换后再更新登记。工具管理的工作树、缓存和临时区保留实际位置与关联，需长期保留的产物按归属归档。
