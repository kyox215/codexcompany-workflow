# 经理、专业岗位与验收

## 组织和责任

一个经理会话承接当前用户，按需使用产品与研究、设计与内容、工程、质量与发布、安全与数据、知识与运营等专业能力。产品/体验负责用户路径和取舍，工程负责实现、接口和恢复，QA 负责复现、独立复测和指出缺证。部门负责人可整理依赖和建议，派工和验收由经理负责。模型与推理档位沿当前项目和宿主可用配置，用户指定优先。

- 先核最新执行安排、当前所有者和授权。选择最少的必要岗位，用[最小任务包](templates.md)传必要资料。经理核对实际任务号与执行关联，明确文件、设备和环境所有权。内部执行和用户聊天用不同类型记录，内部 ID 不能当原生聊天 ID。
- 同目标返工复用能接续的原执行。新目标或跨项目另给最小上下文。员工按原岗位执行，只在当前执行会话回交，协调、外发和启动其他执行由经理依据授权处理。
- 并发只用于拥有独立输入、文件或设备范围的工作。共享文件顺序交接，写前重读，保留其他窗口增量。容量不足就排队。父子任务表达目标拆分，依赖表达先决条件。阻塞写明原因、责任人、解除证据和下一步。
- 工作停滞时整理已经验证、被排除和仍未知的条件。连续两轮无实质进展，换一个有证据依据的诊断办法，或给出需要人类或外部状态解除的具体条件。

## 复杂需求与自主迭代

跨模块、数据写入、权限、用户体验与可靠性取舍常需要多人视角。日常问答、微改和单专业即可完成的工作走短路径。

1. 经理给出可观察目标、当前候选、输入证据和验收点。
2. 产品/体验走用户旅程，工程核数据与故障路径，QA 使用独立样本。经理组织至少一次相互质疑和答复，记录分歧、证据、纠正和决定。
3. 指定作者实现能完整交付的最小切片。独立 QA 先复现已证问题，再核原场景、相邻回归和适用的失败恢复。发现旧测试不适用时，单独记录与产品缺陷的差异。
4. 仅对证实的缺口返工和定向复测。经理给出用户路径、取舍、结果、未验证范围及下一步。缺角色时排队或请项目既有独立验收者，等待期间可先完成不依赖独立验收的工作。

## 验收与版本

作者先验证。执行结果进入任务的可追溯交付目录，记录准确候选、来源、SHA-256 或提交、环境、时间、预期和实际结果。经理回收执行结果并按项目门禁接收子任务，核依赖和成果。父任务进入审阅，绑定要求的独立证据后结束。成果、依赖或候选变更使受影响的验收证据需要重核。采用现有任务系统的实际状态名和入口。

区分代码存在、构建通过、合成验证、端到端行为、真设备/真账号与生产上线。外部写入回执之外，按权限读回实际结果。记录成本时只用可靠的用量或费用。环境、权限、模型身份或用量无法核实时写未知。

## 桌面与外部动作

有足够的专用接口时用专用接口。必须操作前台桌面时先用 Use Computer。不可用、失败或控件不适配时，先观察是否已发生动作，再用当前环境允许且已具备的 agent-desktop 接续。切换工具保持原执行者、授权和目标窗口。

同一桌面上争用焦点、输入法、键鼠或剪贴板的操作一次由一个执行者完成。交接记录设备、窗口、完成步骤、当前所有者、释放条件和下一个执行者。独立后台能力以实际验证为据。工具返回成功后查看真实结果；失败或超时后先确认现场，避免重复提交。

发布、部署、生产写入、付费或权限操作按本轮授权及平台门禁。确需用户决定时先准备具体候选、影响和待批准动作。先完成已授权且不依赖该决定的工作。
