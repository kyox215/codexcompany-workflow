# 项目接续、记忆与留档

## 一次接续检查

确认适用规则和真实工作目录。多项目环境以最具体的已登记项目根确定命名空间，同时核对原生项目、聊天绑定与任务归属。共享原生项目 ID 时再核工作目录及实际绑定。只查本项目最新用户请求、纠正、交接、权威任务状态和必要原文。

有既有任务系统时，在其权威入口一次查回任务、执行、依赖、问题及成果。使用已知真实任务号或请求键。精简结果按计数或游标展开所需部分。索引是导航，确认原文后才能说已读。实施前重核易变状态和当前归属，避免并发执行同一任务。

| 当前状态 | 处理方式 |
| --- | --- |
| 精确目标已完成 | 核对应候选与验证证据，回读已有交付。新增要求只处理差异。 |
| 未完且原执行可恢复 | 读取交接与前置条件，沿原任务和执行接续。 |
| 其他窗口仍在执行 | 只读核对和回收，等待真实移交。 |
| 原执行不可恢复 | 核对归属、权限与保存交接，记录真实新执行，保留原关联。 |
| 阻塞 | 查解除责任人、下一动作和证据，先完成可独立推进的部分。 |
| 仅标题相似 | 核项目、范围、任务键和最新人类来源，确认后才决定是否复用。 |
| 资料缺失，无法判断是否已有任务 | 从允许查阅的同项目来源补证，注明缺项。将依赖任务归属的登记与派工留待确认。 |
| 核实没有对应目标 | 有正式工作再登记新任务，使用实际返回 ID。 |

## 可移植的落点

按[目录与归档模板](project-layout.md)核对分类、`sourcePath`、`reportPath` 和任务交付位置。已有项目沿原目录、规则和任务系统。新项目先选稳定唯一根，核命名冲突与现有执行。明确源码、构建、设计、导出和报告的归属及输出位置。只建立当前需要的目录。历史路径有依赖时等完成可验证的迁移再切换。

原公司部署使用项目登记、SQLite 任务库、只读接续入口和项目交付目录。采用公开版时直接映射到团队已有的登记与任务系统。单人项目可在既有项目文档保留一份简明接续记录，以[交接模板](templates.md)保存观察结果；当没有任务库或旧执行 ID 时如实写明。使用一个权威状态来源，交接是带截止时间的快照。

## 记忆的有效性

| 资料 | 使用方式 |
| --- | --- |
| 项目规则与最新用户决定 | 当前适用的执行规则与授权来源。 |
| 稳定偏好 | 按项目或通用范围保存，有纠正时用新来源更新生效结论。 |
| 业务规则、品牌和技术栈 | 放在对应项目，使用前核实际版本。 |
| 任务、依赖、归属、阻塞、验收 | 写回约定的权威任务系统。 |
| 一次性授权、历史决定和截图 | 保留来源及适用范围。动作前核对授权是否覆盖当前目标、资源和操作。 |

记忆记录包含确认日期、类型、内容、项目/任务范围、可定位来源、有效性及替代关系。建议、合成示例、推断和用户决定分开。经理在适用规则和授权下更新现行记录。员工回交建议。写前重读，保留并发增量。旧记录用于追溯，冲突时采用当前有效决定，并保留变更来源。

## 交付与聊天留档

只保留当前项目获准保存的可见消息、必要附件和工作证据。记录来源、真实标识、覆盖截止、缺失项、环境与文件哈希。索引包含保存的位置与覆盖范围，方便下次按任务读取。临时交接需要长期使用时，将已核实副本保存到授权的项目交付位置。

归档原生聊天前按项目约定确认授权和留档完整性。保留可回读的来源与内容摘要，明确缺失附件、消息或 ID。恢复时复核最新用户请求、任务所有权和覆盖截止。平台发现技能、保存索引、实际读取、独立测试、全链路运行分别记录。跨窗口同步、后台监听与钩子执行以实际验证为准。
