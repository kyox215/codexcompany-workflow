# 按步骤选择专业技能

本包提供工作流和模板。以下名称用于发现环境里已经可用的专业技能。按当前任务使用一个主技能，补解决具体缺口的参考，读实际版本的正文。先核平台与文件类型、用户已定的设计主体及运行时。安装、工具发现、正文读取、连接、权限、样例通过、实际项目应用分别记证据。

| 工作 | 优先方法与可选技能 |
| --- | --- |
| 新项目归置 | 按现有根与隔离规则。确有初始化或隔离要求时用 `project-isolation-bootstrap`。 |
| 需求澄清与领域 | 复用已有答案，问影响结果的未知。用户要求深访或压力测试时用 `grilling`。对象或术语容易混淆时用 `domain-modeling`。 |
| 可验收规格 | `to-spec` 或本包规格卡。记录已确认的测试边界，沿同一 REQ 复用。 |
| 工程拆分 | `to-tickets` 或工程切片卡。模块边界问题按需用 `codebase-design`。明确有重构需求时再采用 `improve-codebase-architecture`。 |
| Web 设计与实现 | 用 `ui-design-workflow` 组织视觉、响应式实现和浏览器验收，按需用 `impeccable` 做设计判断。新美术方向才用 `design-taste-frontend`。手机 Web/PWA 特有问题使用 `mobile-native`。 |
| 原生 App | 按当前平台加载 `impeccable` 的原生指导。Swift 实现用 `write-swift`，按现有 Xcode 工具链验证；有可用 iOS 构建工具时读取实际工具说明。React Native/Expo 用其原生组件、导航和对应移动技能。交互原则可借鉴 `apple-design`，实现沿项目平台。 |
| 设计工具与交互 | 有现成设计源就复用。Figma 读写遵循对应技能前置。明确需要动画、组件或动作模式时使用匹配的专业技能。 `review-animations`、`prototype`、`pick-ui-library` 等按实际技能的显式调用条件。 |
| Bug、测试与审查 | `diagnosing-bugs` 先复现定位。用户要求测试先行或有重要行为回归时采用 `tdd`。 `code-review` 的完整方法需要在明确基点上做规范和规格两轴审查。安全范围明确时用 `security-audit`，保留独立验证和环境限制。 |
| 发布与交接 | 按实际平台准备候选和发布证据。 `handoff` 的临时交接需要按项目规则另行留存。 |
| 内容交付 | 结构图用 `anatomy` 或匹配的图解方法。发布视频按产物目标在 `brag-slim` 与 `openfilm` 中选择。验证实际导出、素材范围和事实。 |

## 第三方技能的衔接

- 保留技能自己的显式调用策略与前置条件。缺可用工具、连接、执行者或平台能力时，用本包的规格、切片和审查清单完成可行部分，并标注采用的方法和证据范围。
- 已有任务系统时提供项目、真实任务号、REQ→规格→任务映射、依赖、基点和验收要求。默认将规格和切片留在用户指定位置。外部工单或评论按对应授权执行。
- 设计、工程、验证都沿已确定的品牌、栈与用户行为。新技能和旧记忆用于提供方法和线索。用户改变要求时，按变化的 REQ 更新相关产物。

## 已有应用研究

有源码或公开资料时先用足够回答问题的来源。仅研究可见页面、交互与视觉时用浏览器或 UI。需要研究获准的二进制、托管程序集、JS/WASM 或包内资源时，可在当前环境使用已连接的 REA 或项目认可的静态工具。

先核目标材料、授权、宿主、分析类型和实际工具输入契约。固定版本或样本哈希，从最小只读材料开始。报告入口→函数/资源→可能行为的映射，附位置、工具与 Evidence 引用。区分原始字节、静态推断和实际运行，标明截断、失败和覆盖范围。用同一 REQ 把事实交给规格、设计与验收。执行样本、访问设备或服务、实施功能需要相应授权。
